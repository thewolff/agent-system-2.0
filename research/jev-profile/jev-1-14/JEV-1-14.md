## 1. Post text (CITE, verbatim-faithful condensation)

- TL;DR: improved Jev 1.14.0 plus experimental "danger zone" features: images, a new type, longer context.
- Philosophy: dreamer features ship behind "danger zone" API headers; "still way too much jaggedness for us to vouch for these for production use cases."
- **Composable Images.** `jev-1.13.0` "was multimodal all along". Images are composable via find-and-replace in `assets`; usable in `state`, `instructions`, or `criteria`. "all models (Jev included) perform worse on multimodality over pure text. Breaking down questions into the simplest possible decompositions helps a lot." Header: `TypeSafe-Danger-Zone-Images: true`.
- **Types Beyond Decisions.** New type `box`: "returns a single bounding box - no type errors allowed." Enabled "only for `jev-1.14.0`".
- **Long context.** Jev supports longer context than production enables; limited on purpose because longer contexts are less reliable. "we strongly recommend limiting context length, you no longer have to". Header: `TypeSafe-Danger-Zone-Long-Context: true`.
- **Opt-in to help us.** Opt-in lets TypeSafe analyze queries to find jaggedness; "We will still not train on your queries".
- **jev-1.14.0** released under `jev-preview`. "small, subtle improvements to everything … we expect the largest gain in multi-lingual support." "`jev-latest` will be updated to `jev-1.14.0` in a week. `jev-1.13.0` will be available for a while." 60 days' warning before 1.13.0 deprecation, 30 days for 1.14.0; a deprecation policy will be published first.
- **Measuring Intelligence.** Internal numbers, caveats: best guess, will evolve, "don't expect them to be consistent"; "Always favor your own experimentation and evals"; open-weight comparators only; "likely biased towards our models".
- **What's next.** Mostly "beautifully boring" releases.

## 3. Docs findings (CITE)

**/go/images** (Concepts > Images, marked "Dreamer-ready"):
- Header `TypeSafe-Danger-Zone-Images: true` on every request containing an image or Box question; off by default.
- Top-level `assets` map: key = reference string; value `{type?: "image", format: "png"|"jpg"|"jpeg", data_base64}` or `{part}` for multipart (part wins if both).
- References are plain-text matched anywhere in strings; whole-value match first, then left-to-right non-overlapping. Every asset must be referenced or 400. Each use adds another image copy, counted toward the expanded request limit. Object keys are not replaced. Answers echo the reference, not the image. Reference ≤1,024 bytes; all references ≤65,536 bytes. Recommend a fresh UUID per image.
- "Jev 1.13 and Jev 1.14 both accept images. Box questions need Jev 1.14." SDKs (Python `Image(Path(...))`) create references.
- Format/answers/limits "can change between releases".

**/go/box** (Primitives > Box, "Dreamer-ready"):
- `{"type":"box","instructions":"the coffee mug in \`photo\`"}`; no `criteria`. Needs `jev-preview` or `jev-1.14.0` and the images header.
- Answer: `box: {top,bottom,left,right}` each 0–1 fractions from top-left, plus `confidence` 0–1. No recommended threshold yet.
- No "not found" answer — always returns a box; pair with a Noul "is X present". One box per question.

**/models** (Reference > Models):
- jev-1.14.0 and jev-1.13.0: price $42/Btok = $0.042/Mtok input, output free; context 64k per-request / 32k per-question; table lists Input "Text" for both (contradicts the images page — docs inconsistency). 1.14 "available from October 14, 2026".
- Long context: header `TypeSafe-Danger-Zone-Long-Context: true`, works on 1.14 and 1.13, raises both limits to 262k; same per-token price; "slower and less accurate".
- Aliases today: `jev-latest` → `jev-1.13.0`, `jev-preview` → `jev-1.14.0`. "If you have tuned confidence thresholds against one version, send that version's ID instead of the alias". Response `model` field names the version that answered.
- Language: English best; other languages handled less well.

## 4. What changes for us (relative to ../JEV-PROFILE.md)

- **CITE** `jev-latest` moves to 1.14.0 about one week after 2026-10-14 (≈2026-10-21). **GUESS** Every call site on `jev-latest` that accepts any `typesafe/jev-*` (receipts audit score.ts, plumb-rank rank.ts per JEV-PROFILE §5 rule 5) will silently change model then; the as2 classifier pinned to `jev-1.13.0` fails closed on mismatch so it is unaffected. The capability card should say measurements are 1.13.0-only and are not evidence for 1.14.0.
- **CITE** 1.13.0 stays "for a while", 60 days' notice before deprecation. **GUESS** Pinning 1.13.0 is safe for ≥60 days after any notice; re-measure on 1.14.0 before switching the pin (calibration.json is 1.13.0-specific).
- **CITE** Vendor's own chart: 1.14.0 intelligence 60.0 vs 58.9, calibration error 1.6 vs 1.8, same cost. **GUESS** Small delta; vendor flags it as untrustworthy and biased. Not a reason to switch without our own eval. Largest claimed gain is multilingual, which our workloads barely use.
- **CITE** Images work on 1.13 and 1.14 behind a header; `box` only on 1.14. **GUESS** Card entry: "images / box — untested by us, vendor-labelled not production-ready".
- **CITE** Long context to 262k behind a header, slower and less accurate. **GUESS** Card should keep the 64k/32k default as the stated limit and list long context as untested.
- **CITE** Org-wide opt-in "Help improve TypeSafe models" lets TypeSafe read inputs/outputs (no training). **GUESS** This is a data-handling decision for Jo, not for a lane; default leave off.
- **CITE** Docs table says Input "Text" for both models while the images page says both accept images — vendor docs inconsistency worth noting on the card.
