title: A workload's close archives its scratch root before removing it, and the daily sweep expires the archives
status: building
workload: none
pr: none
---
**Why.** On 2026-10-28 at about 22:17Z the close of workload `wl-mvs2x210k5ifkz` removed its scratch root seconds after the lane's done-because (`en-mvsodoos0xh1rm`) named the review-cost replay's `REPORT.md` inside it. The report and all its evidence were deleted, and the lane's two "keep scratch" messages were held until after the removal. Jo approved replacing the delete with an archive.

**What.** `closeScratchRoot` (`surface/src/close-entry.ts`) now calls `archiveScratchRoot`. The root is first renamed aside to `.removing-<id>-<hex>` (`detachChild`, `surface/src/scratch-remove.ts`), so nothing that writes by the root's path reaches the tree being archived. `archiveDetached` (`surface/src/scratch-archive.ts`) then writes it to one `.tar.gz` at `~/agent-scratch/agent-system-2.0/scratch-archive/<UTC YYYY-MM-DD>/<wl>.tar.gz` (a sibling of the scratch base, so no scratch sweep sees it; `<wl>.2.tar.gz` and so on if a name is taken). The steps: read the tree's manifest (every entry's relative path, type, size, mode, SHA-256 of a file, link target, inode, and mtime and ctime in nanoseconds; a socket, FIFO or device refuses); check the archive volume has room for the archive, its verification copy and 1 GiB; write `<final>.partial-<12 hex>`; extract it into a private `.verify-<16 hex>` directory and compare that copy with the manifest entry by entry; hash it, chmod 0600 and hard-link it to its final name; read the manifest again and compare identities, dropping the archive on any change. Only a verified archive lets `purgeDetached` run. Any failure renames the tree back to its own name (or says where it was left) and records `scratch-remove-failed: <wl> <root>: not archived (<reason>); the root is kept`. A success records `scratch-archived: <wl> <archive> <bytes> <sha256>` and then `scratch-removed: <wl> <root>` on the standing workload. When the done-because names a path inside the root (as written, physically, through `$AS2_SCRATCH` or `~`), the close result checks it against the archive's members: archived as `./<path>`, not in the archive, a `..` path not checked, reached through a symlink (the archive holds the link, not its target), or kept with the root. The daily sweep (`surface/scripts/scratch-sweep.ts`) detaches each root it removes under the ledger's write lock, then archives and purges it the same way, one root at a time so one root's failure never stops the others. A root whose archive fails is renamed back and reported as `archive failed` (exit 1). A `.removing-*` leftover idle for 3 days is archived like a root before it is removed (its archive name drops the leading dot), because its name proves nothing about an archive.

**Expiry and disk guard.** The profile config's `scratchArchive:` block (`profile/config.yml`) holds the settings. `expireDays` (default 14): the sweep removes archives older than this, by mtime, and records each as `scratch-archive-expired: <archive> <bytes>`. An archive is a name ending `.tar.gz`; a partial is only the writer's exact `.tar.gz.partial-<12 lowercase hex>` suffix; every other name, and every `.verify-*` directory, is never removed. `requireOffsite` (default false): when true, an old archive expires only once `<archive>.offsite` exists beside it. An offsite copy job writes that marker once its copy is confirmed; the sweep removes the marker and the job's `<archive>.attempts` and `<archive>.stuck` sidecars together with their archive, and never touches a sidecar whose archive is gone. `minFreeGib` (default 20): the sweep's `scratch-disk:` needs-you line also opens when free space on the scratch volume (statfs) is under this value, and its `scratch-disk-ok:` waits for both bounds. `$AGENT_SYSTEM_SCRATCH_CONFIG` replaces the installed config as the source (tests). The sweep takes `--now <ISO time>` so its tests run on one fixed clock.

**Writers.** Before the final identity check, `lsof -n -P -F pn +D` over the detached tree (30 s limit) must show nothing open: a write through a descriptor opened before the rename aside changes no path and could land after any check. A file still open, or an lsof that is missing, times out or errors, fails the archive, which is dropped, and the root is renamed back and kept; the daily sweep retries it. Without lsof nothing is removed. A sidecar a new archive would collide with (`.offsite`, `.attempts`, `.stuck`) holds its name, so a new archive never inherits an old offsite marker, and once an archive is unlinked at expiry the expiry is recorded even when a sidecar cannot be removed. Not covered: processes of another user, which lsof cannot see.

**Revert.** Revert the PR. The close goes back to deleting roots outright. Archives already written stay on disk and are no longer expired, so remove `~/agent-scratch/agent-system-2.0/scratch-archive/` by hand once nothing in it is needed.
