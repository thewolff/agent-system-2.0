**Built on branch `wl/wl-mv7gidggnlkem8`.** Workload `wl-mv7gidggnlkem8` (normal stakes, plan revision 6 at `~/agent-scratch/agent-system-2.0/wl-mv7gidggnlkem8/PLAN.md`, six review rounds, reports `REVIEW-plan-r*.md` beside it). **Why:** a `pending` row was `<option> <id>  # <subject> · <recommendation> · also: …`, its subject the question body cut at 80 characters, so `pending` alone told Jo neither which work a row belonged to nor what was being decided. **Jo's choice:** *authored* (`in-mv7ho4lzs1bhts`): the asker writes the name and the ask when it creates the row, and rows raised earlier are described from a reviewed manifest. No runtime summariser and no first-sentence heuristic.

**What changed.** Each open row is one entry inside the block's fence: `# Work: <name>`, `# Question: <ask>`, then `# Context:` (ceiling and review-limit questions: the machine's first body line, marked at raise, so it does not move as spend grows), `# Request:` (a reserved action's exact held request, uncut, with Unicode Cc, Cf, Zl and Zp characters printed as code-point escapes so bidi or zero-width text cannot hide or reorder it), `# Default: <option> (<recommended by …, or first option>); alternatives: …`, any `# Metadata:` diagnostic, then the `<option> <id>` command last. An open plan question keeps `plan for q-…: <path>` on the one line under its command. Rows with no options or several-word options stay in the fence and end `# Answer: in words; no pasteable command`; prompt waits become uncounted cards in the fence whose question is the real choice ("Will you answer the <tool> prompt in <lane>'s session, or end that session?") with no command. Ordering, the answer count, recommendation precedence, reserved decisions and all-or-nothing answers are unchanged.

**Authoring.** Names and asks are `assumption` entries under two new control prefixes, `work-name:` and `question-pending:`, each bound to its row by a SHA-256 of the row's source fields (`surface/src/pending-details.ts`); no schema change, `lane_record_entry` refuses both prefixes, and neither counts as a `done-because:` or enters the decision log. `orchestrator_open_workload` and `orchestrator_schedule` take a required `name`; `lane_raise_question` a required `ask`, kept apart from the plan question's exact body; `orchestrator_raise_question` a required `ask`, plus a `name` only when it is about no workload. A name is 1–80 and an ask 1–320 Unicode code points, one plain line, no control, format or line-separator character, no fence; an ask ends with `?`; a name is not a bare ledger id. Each is checked before anything is written and written with its row in one transaction. A workload with no name never refuses a new question; its rows show `# Metadata: missing name for wl-…; pending descriptions need initialization` and keep their default and command. The standing workload, its reserved actions and unbound waits show the fixed name `Orchestrator decisions`; the reserved ask is always "Should this reserved action be approved or denied?", and the gate's writes, identity and the wake are untouched.

**Paste.** The surface strips every generated line it can match to a live row and never forwards one to Ilex. Jo copies with `/copy` (no argument: the picker, then the whole `pending` message, raw) and pastes the whole block, one entry from its `# Question:` or `# Default:` line down, or bare commands. A pure generated block with no command is consumed and echoed on interactive and RPC input alike; generated lines plus Jo's own sentences with no command are refused whole, the sentences shown back; a block from before this change is refused whole with an instruction to run `pending` again, while bare old answer lines, `# …` tails included, still parse. A row arriving after the copy does not invalidate it (the heading count is matched by shape, not value). Complete commandless question and prompt-wait cards copied without the heading/fence are now recognized by their full field structure, including a legacy question with `# Metadata: missing ask` instead of `# Question:` and a wait with no Work name. A pure current card is consumed without Jo input or a model turn on interactive and RPC; a whole card stale, edited, reordered or assembled from multiple live entries refuses atomically even when some fields match live rows. A card plus Jo's prose with no command refuses and holds the prose; partial metadata-looking fragments remain ordinary prose. The fallback before_agent_start reads the same cards without recording Jo input but cannot suppress a host turn that has already started.

**Pair and legacy boundary.** A stamped ceiling or review-limit machine question offering `pair` has a fixed single-sentence ask naming the stop and the switch to `user-driven`, without changing its default; unsupported options still require an authored ask. A legacy unbound question can lack both its work name and ask, showing `# Metadata: missing name for q-…` and `missing ask for q-…` with no Work or Question line. Its complete headerless commandless card (with multiword options) is compared as a whole against one live entry and consumed without Jo input; a mixed, edited or answered card is refused, while a partial field fragment remains prose.

**Known risks, accepted in the plan.** An untouched whole block approves every reserved action listed: its default is `approve`, labelled "NOT a recommendation", and the guide says so. A long `# Request:` line enlarges `pending` and the `back` and quiet-return context that carry it; visibility wins. A mouse selection wrapped at the terminal width, a prompt-wait card whose session has since resolved, and a `# Metadata:` line copied before its row was described all refuse the paste safely; Jo runs `pending` again. `before_agent_start` remains the fallback for a host that delivers no input event: it recognises the block and writes no Jo-input receipt, but does not promise to suppress that host's model turn.

**Rollout (required before done; a green PR is not done).** After the PR merges: fast-forward the running checkout, run `bash install/install.sh`, and restart as2 and relaunch running lanes, since a running session keeps the old tools and the old `pending`. Then a lane runs `bun surface/scripts/pending-descriptions.ts snapshot` and `export` (read-only), authors every gap's name or ask against its full source into a manifest in the plan directory above, and has another lab review every entry against that source. Ilex applies the reviewed file with `orchestrator_describe_pending { manifestPath, sha256 }`, the digest of the exact reviewed bytes; it fills gaps only, never replaces a value, refuses the whole file when a submitted open row's source has changed, and reports rows raised since the export as `missing` for a further reviewed file. A closed workload that an open orchestrator question still names with no name is `unfillable`: it takes no import, and the gap clears only when Jo answers or withdraws that question. The workload's `done-because:` is recorded only after `bun surface/scripts/pending-descriptions.ts check --manifest <path> --sha256 <hex>` exits 0: zero `missing` and zero `unfillable` descriptions and every stored value equal to its reviewed one, read from the live ledger.

**Rollback.** Revert the PR, then fast-forward, install and restart as above. The ledger schema and every raw row are untouched; the `work-name:` and `question-pending:` entries stay, and the old `pending` ignores them. Two effects are not cosmetic. The old decision-log renderer includes them as JSON assumptions. The old `doneBecause` does not know the two prefixes, so such an entry written by a holder or the surface after a workload's `done-because:` supersedes that receipt, and close, launch and release refuse as if no receipt existed. Remedy: when the workload's acceptance still holds, its holding lane records a fresh `done-because:` after the retained entries. Never delete ledger entries to clear it. Reverting removes this file, so the revert PR carries this remedy in its description.
