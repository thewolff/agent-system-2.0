Workload `wl-mv654hoqwpfhmo` (production stakes), PR-K of its plan (`~/agent-scratch/agent-system-2.0/wl-mv654hoqwpfhmo/PLAN.md` § 10, approved by Jo). Item 9 of the plan's brief asks to fix the Kimi parse first: Kimi review rounds were recorded `blocking unknown` far more often than OpenAI's.

**The split (A10, `~/agent-scratch/agent-system-2.0/scratch/wl-mv654hoqwpfhmo/A10-SPLIT.md`, read from the ledger and the hands' session files on 2026-10-19).** 241 review rounds ran on Kimi; 157 were recorded `blocking unknown` (OpenAI: 12 of 657).
- 52 had no reply, which no parser fixes: 40 Moonshot 429 balance suspensions, 5 403 subscription refusals, 3 provider `unexpected_state` errors, 1 connection error, 3 stopped before any reply.
- 105 replied. In none of them did the yield payload or OMP's `<agent>.md` (what the classifier read) hold a block of the contract's shape that `parseFindings` missed: zero conformant misses, so the parser is unchanged.
- 96 of the 105 wrote a valid block in their own assistant text and yielded the findings without it (as JSON objects, prose, or a pointer to "the block above"): 37 in a text-only turn before the yield, 59 split around the yield call, the closing fence a text part of its own after it.
- 9 wrote no valid block anywhere: 8 no block at all, 1 a block with a kind outside the list.

**The rule (Jo, q-mvfor0be7rezgg: `transcript`).** `handFindings` (`classifier/extension.ts`) reads, in order, the yield payload, then `<root>/<agentId>.md`, then the hand's session file `<root>/<agentId>.jsonl`. The first that parses wins, so a payload or `.md` that parses today gives the same result. The session file is a new findings source: the session OMP itself writes for the hand in the lane's artifacts directory (`task/executor.ts`), beside the `.md`. It is not a result delivered to the lane, and SPEC § B3's list of where a hand's result reaches the lane is not changed by this item. From the session file it reads the hand's final assistant text: the text parts of the assistant messages after the last user message and after the last assistant message that calls a tool other than `yield`, joined in session order, one per line. The second cut is OMP's own harvest rule (`startedMoreWork` in `task/executor.ts`): a turn that starts more work makes every earlier report text stale, its own text included. So a block split around the yield call rejoins, and a block turn followed by a `developer` reminder and a yield-only turn is read (a `developer` message resets nothing). The last `review-findings` block in that text is parsed by `parseFindings`, unchanged. Nothing outside the window is read: not the brief (whose example block below is a placeholder), not a reply an earlier user message superseded, not a draft block the hand then revised with more tool work, and not the brief's example echoed before the work. A user message delivered to the hand after its block, such as a peer or IRC message, also resets the window, so that round reads `unknown` unless the hand writes its block again (A10 has one such round, `sl-mv8d-int-capture`). A session with no user message reads as nothing. A malformed or unterminated last block stays `unknown`, as does a missing or unreadable session file. Lines that are not `"type":"message"` records are skipped before they are parsed.

**The example block.** `REVIEW_FINDINGS_PARAGRAPH`, appended to every review brief, now ends with one complete block that `parseFindings` parses, fenced as `review-findings`: a fail-safe placeholder holding one finding, `{"severity":"blocking","kind":"other","title":"unreplaced placeholder from the brief's example block: the reviewer sent no findings of its own"}`. The title describes itself, so it reads correctly where it lands (the `review-round:` entry, Jo's round-limit question). The prose above it gives the entry shape and says the block for a review with no findings is the empty list, `{"findings":[]}`. The empty list itself was not used as the example, because a reply that copied the example verbatim would then read as a clean review it never made. The placeholder copied verbatim reports one blocking finding, so the round fails visibly.

Already-settled rounds are not recounted: the new source applies to rounds that settle after the merge, and the plan's § 11.5 report compares the unknown rate before and after the merge date.
