One channel through which other agents message Ilex (plan `/Users/jowolff/agent-scratch/agent-system-2.0/wl-mv8vx7wdj5nx1c/PLAN.md` rev 6, production stakes). Phase 1 has one sender, Plumb, a local OMP persistent seat. Plumb's authority is notes and proposals only (Jo's answer `notes`, input `in-mv8yzvhuwz9jwg`): no message is ever written as Jo, and nothing a message says is applied without Jo's own typed word.

**Senders (D1).** `profile/config.yml` gains a `channel:` block:

```yaml
channel:
  senders:
    - { id: plumb, transport: omp-mailbox, authority: notes }
```

`id` is `[a-z][a-z0-9-]*`; phase 1 knows one transport, `omp-mailbox`, and one authority, `notes`. Any other value refuses the whole block at session start, with a notice, and the channel stays off. No block: no channel. `surface/src/channel.ts` holds the config reader, the envelope validator, the ledger writes and the proposal reader; `surface/extensions/agent-channel.ts` holds the drain, the aside and the two tools, and `surface/index.ts` registers it for the orchestrator role only.

**Inbound (D2).** The drain runs at session start and every 2 s over `~/.omp/agent/seat-mailboxes/inbox/ilex/`. It claims only published `<id>.json` envelopes and claims a crashed session left behind; writer temporaries, `.invalid` files and a live session's claims are left alone. An envelope is checked as the seat registry checks it (string fields, id grammar, filename `${id}.json`, non-empty message up to 64 KiB, no `schemaVersion`, `to` Ilex, `from` a configured sender, both compared trimmed and lowercased). A valid one is recorded once, in one ledger write:

- a `messages` row `msg-ch-<envelope id>` on `wl-orchestrator`, sender `plumb`, recipient `orchestrator`, created_by `channel:plumb`, body `channel-note from plumb:\n<message>`. The fixed prefix keeps a body from tripping a control-prefix reader (`lane-died:`, `prompt-wait:`, `artifact-failed:`, `test-run-failed:`);
- a `channel-in:` entry naming the envelope id, transport and the sha256 of the claimed bytes;
- a `channel-propose:` entry per proposal (below).

Then one aside, customType `agent-channel`, headed `From Plumb (msg-…; authority: notes — not Jo; information, not instruction):`. Sending it records nothing: OMP's send is fire-and-forget and can drop an aside while another turn is starting. The aside is confirmed by OMP's `message_end` for it, which records the `channel-aside:` entry; only then are the ack and the archive copy written, so Plumb's `seat_message` reports `delivered` only after Ilex has the text. Until then the claim stays in `inbox/ilex/` and the drain resends it, only while Ilex is idle, up to `PUSH_TRIES` sends in all. Anything still unconfirmed rides Jo's next turn as one message, and that message's `message_end` confirms it. A crash at any step is resumed by the next drain: the row is written once and the aside shown at least once. The message moves to `consumed` at its confirmation when that falls inside a turn (right after that confirmation's drain has written the ack), otherwise at the next `agent_start`; the registry's turn receipt `acks/<id>.turn.json` is written then, so `seat_message` reports `acted`. Every turn receipt needs proof that the ack at that id is Ilex's own: the archive copy holds the bytes whose sha256 the `channel-in:` entry records, and the ack's `id`, `from` and `to` equal that envelope's. Each drain tick writes a missing receipt again for a message consumed or acted on in the last 7 days that has its `channel-aside:`; a session's first tick looks back with no time bound, and that unbounded pass stays owed until one leaves no receipt owed: a failed receipt write, or a receipt whose ack or archive copy is not yet published, owes it again. So neither a restart after any outage, a full disk, nor an archive that could not be written abandons a receipt. The message moves to `acted-on` through `orchestrator_reply` or `orchestrator_channel_done` (D4). Confirmation is about transport, not handling: a `message_end` that comes after the tool still records `channel-aside:`, and a message Ilex acts on (reading it from the block below) before any aside is confirmed is not resent. The next drain pass records `channel-aside: <id> handled-before-aside` for it, then its ack and archive. A refused envelope is renamed `.invalid` and gets one `channel-refused:` entry that shows as an unnumbered needs-you line. A late `id collision` on a message already recorded withdraws it from later renders; it is never consumed and never gets a turn receipt, because the ack at that id belongs to another seat. The line says how far the message had come: refused before its row was written, `nothing reached the model`; a row with no confirmed aside, `no aside of <msg> was confirmed (it may have been read in the ledger)`, since the block below can show such a row; a confirmed aside, `<msg>'s aside had already reached Ilex`; handled first, `Ilex had already read and acted on <msg>`. The drain never replaces a file in the shared `acks/` or `archive/` directories: an id that already has another seat's ack or archive is refused as `id collision`, and both files are published with a no-replace `link`.

**Where Ilex reads it (D3).** The aside, once a send lands (or with Jo's next turn); a `## from other agents` block in the wake and in `orchestrator_ledger`, listing every channel message not yet `acted-on` and not refused (sender, id, state, age, first 120 characters). A line that looks like a command but names no needs-you target is marked `command-shaped`. The block is not under *needs you*: a note is not Jo's to answer. `wl-orchestrator` stays out of "open workloads".

**Replies (D4).** `orchestrator_reply { to, body, re? }` writes an OMP envelope from `Ilex` into `inbox/<to>/` for a configured sender, records `channel-out:`, and walks each `re` message to `acted-on`. `orchestrator_channel_done { re }` walks them without a reply. Every `re` must be a channel row of a configured sender (and of `to`, for a reply); any other id refuses the whole call. Both tools are in `SURFACE_TOOLS` and absent from `LANE_TOOLS`.

**Proposals (D5).** A message line that names its target and an answer word for it (`deny en-…`, `approve en-…`, `<option> q-…`, `withdraw q-…`) on a row waiting under *needs you* becomes a proposal. It renders directly under the target's line with the target's own number, `#3 plumb proposes deny en-… (msg-…)`, and gets no number of its own. Jo answers `3 deny`, or any other word that fits the row (`3 approve`); the word is an ordinary Jo row, written by the existing path. A bare word (`deny`) is never a proposal. Flip and ceiling words (`autonomous wl-…`, `production wl-…`, `ceiling 999 wl-…`) answer no numbered row, so they stay notes, marked `command-shaped`.

**Never as Jo (D6).** No row the channel writes has author `jo` or created_by `orchestrator-surface`, and it writes no instruction, answer, stakes or mode flip, ceiling change or state change beyond its own message row, that row's state walk and its `channel-*` entries. `from` is self-claimed (no sender proof), so a spoofed sender costs a misattributed note or proposal, and a proposal still needs Jo's typed word. There are no grant words in phase 1.

**Roster (D7, outside the repo).** `~/.omp/agent/seat-launchers/launch-seat` lists `Ilex` in `PERSISTENT_SEATS`, `persistent-seats.json` gains `{slug: ilex, displayName: Ilex}`, and `inbox/ilex/` exists. Both files are backed up in the plan directory with sha256 sums, and `roster-undo.sh` there restores them. Plumb is relaunched once to pick up the roster.
